### Root Causes

1. **Placeholder mismatch**: The test uses `getByPlaceholder('Page title', { exact: true })`, but the actual placeholder is likely different (e.g., `'Title'` or something else). This is consistent with the `R-NAME` relaxation in the S1 manifest, which allows `'Page title'` to be replaced by `'Title'`.

2. **Wrong page opening (B64-D1)**: The page list is returning the first page (Page A) instead of the target page (Page B). This suggests the `pageListScope` or `openPage` logic is not correctly identifying the target page, possibly due to:
   - The page list region not being correctly scoped.
   - The page entry button/link not being correctly identified by title.

3. **Empty body in editor (B64-D2)**: The editor title is populated, but the body is not. This suggests the `openEditor` function is correctly finding the editor title field, but the body field locator is not correctly identifying the rich-text editor.

### Required Fixes

1. **Fix placeholder matching for page title**:
   - Update `PAGE_TITLE` regex to include `'Title'` as an alternative.

2. **Fix page list scoping**:
   - The `pageListScope` function is too permissive. It should be more specific to avoid matching unrelated regions.
   - The current regex `/pages?( list)?$/i` might match "Details" or "Actions" headings.

3. **Fix body field locator in editor**:
   - The `PAGE_BODY` regex includes `'write your page content here...'`, but the actual placeholder might be different.
   - The rich-text editor might not be correctly identified by `[contenteditable=true]`.
